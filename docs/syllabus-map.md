# Syllabus map

Where each module/topic of the course shows up in PlaySync, linked to the concrete file, test or page that demonstrates it.

| Module / topic | Where it shows up | Evidence |
|---|---|---|
| **M1** architecture, three-schema, client-server | React client ↔ Express ↔ MySQL. External level: the snapshot API (`server/src/services/accountState.ts`, `GET /api/accounts/:id/state`); conceptual level: [er.md](er.md); internal level: indexes and InnoDB locks (Stats for nerds → Database, Stepper, Index) | `web/src/components/nerds/DatabaseTab.tsx`, `GET /api/db/overview` |
| **M2** keys, FKs, integrity, NULL handling | PKs; candidate keys `username` and `(account_id, device_name)`; composite FK `(device_id, account_id)`; `CHECK (max_streams BETWEEN 1 AND 10)`; the generated column relying on NULLs not colliding in UNIQUE | `db/schema.sql`; `server/test/schema.test.ts` (rejects a session whose device belongs to another account) |
| **M2** ER / EER, mapping | ER diagram, DEVICE specialization (disjoint, total, attribute-defined; mapping 8C), session as a reified relationship, events as aggregation | [er.md](er.md) |
| **M3** FDs, normalization, BCNF | FDs per table; the deliberate 3NF violation in `playback_session` and its composite-FK remedy; append-only audit log | [normalization.md](normalization.md) |
| **M4** indexing, B+ tree, query optimization | Composite index `ix_session_account_status_lease`; `EXPLAIN` / `EXPLAIN ANALYZE`; the **Index experiment** (5 vs ~20,600 locks; other accounts block without the index); the count query in relational algebra (γ, σ) | `server/src/lab/indexExperiment.ts`, `server/test/indexExperiment.test.ts`, Stats for nerds → Index; [concurrency.md](concurrency.md) §6 |
| **M5** transactions, ACID, schedules, serializability | Race runner (write skew), Stepper schedules, the NAIVE schedule as a precedence-graph **cycle**, an interactive precedence-graph checker | `server/src/lab/raceRunner.ts`, `server/src/lab/stepper/scenarios.ts`; `web/src/lib/theory/precedence.ts` (+ tests); Stats for nerds → Theory; [concurrency.md](concurrency.md) §1 |
| **M5** recovery | Fault-injection rollback; `KILL_RECOVERY` (undo log); InnoDB redo/undo as immediate update with WAL, contrasted with deferred update and shadow paging | `server/test/strategies.test.ts` (fault injection), `server/test/stepper.test.ts` (scenario 7); [concurrency.md](concurrency.md) §7 |
| **M6** lost update | Play-counter experiment with four variants (NAIVE_RMW loses ~49 of 50; ATOMIC, LOCKED, CAS exact) | `server/src/lab/lostUpdate.ts`, `server/test/lab.test.ts`; [experiments.md](experiments.md) Table D |
| **M6** lock-based protocols, strict 2PL, compatibility | PESSIMISTIC (locks held to commit); S / X / IX / gap / insert-intention modes in the live lock table | `server/src/strategies/pessimistic.ts`; Stepper lock table (`server/src/lab/stepper/locks.ts`) |
| **M6** deadlocks: detection and prevention | `SERIALIZABLE_DEADLOCK`; `CLASSIC_DEADLOCK` vs `ORDERED_LOCKING`; InnoDB wait-for-graph detection and the `LATEST DETECTED DEADLOCK` report; the global lock-order rule | `server/test/stepper.test.ts`; [concurrency.md](concurrency.md) §4 |
| **M6** multi-granularity locking | `IX` table locks alongside record locks in `performance_schema.data_locks` | Stepper lock table; [concurrency.md](concurrency.md) §5 |
| **M6** optimistic concurrency (validation-based) | OPTIMISTIC strategy (CAS on `state_version`), the correctness argument, and retry/latency trade-off | `server/src/strategies/optimistic.ts`; [concurrency.md](concurrency.md) §2.5; Stepper `OPTIMISTIC_CAS` |
| **M6** timestamp protocols, Thomas write rule | Basic timestamp ordering and TO with the Thomas write rule, simulated step by step (MySQL does not use TO) | `web/src/lib/theory/timestampOrdering.ts` (+ tests); Stats for nerds → Theory |
| **M7** NoSQL, key-value stores, CAP | `REDIS_LEASE`: atomic Lua slots with TTL leases, two-store consistency (TAKEOVER reconciliation), fail-closed behaviour of a single Redis node | `server/src/strategies/redisLease.ts`, `server/src/db/redis.ts`, `server/test/phase7.test.ts`; [experiments.md](experiments.md) |
| Concurrency at scale (beyond the syllabus) | A live crowd of up to 1,024 virtual listeners making real transactions, with live protection switching and repair | `server/src/lab/sim/*`, `/sim`; [simulation.md](simulation.md) |
